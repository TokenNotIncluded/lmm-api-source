### 请求与资金的关键约束

候选路由来自同一个配置快照，最多 8 个。回退仅限当前可证明兼容的上下文上限预占、
协议与用量语义；需要精确计数或依赖上游成本的路径不自动借用其他生成器的预占。
跨组回退保留首组销售报价和账单归属，实际尝试的目标与组另存追加证据。
会话亲和是稳定选路提示，配置、可用性与合法回退可以改变最终目标。

HTTP 429/5xx、超时、读取失败、部分流式输出、工具调用或用量证据，均不能独立证明
请求未受理。明确拒绝必须同时匹配宿主审阅过的供应商契约和完整纯错误回执。
无法确认的结果保留 UNKNOWN 与原预占，通过既有恢复机制处理，不能自动重发或假定零账单。

确认未发送/未受理的最终失败追加 Core 不可变证据，并绑定路由和原报价。
零结算及重启恢复必须能核验这份证据；普通零 token 字段或 HTTP 状态不具有同等效力。
文本按次模式只对可核验完成的请求计 1 次，明确未受理计 0 次，不确定结果保留预占。

### 存量配置与数据

旧 Key 中已经保存的非空 Auto 列表无法仅凭内容辨别当初是用户自定义还是继承快照，
因此本轮不猜测性重写。希望跟随全局的存量 Key 可明确保存为空数组。
日志清理只针对已导入的历史日志；原生计费和恢复证据保留。

数据库增加两个组件，已有 29 组件站点需要
[固定 29 → 31 离线升级](request-operations-upgrade.md)。正常服务启动不会修改结构。
本轮没有操作生产数据库、真实付费供应商、部署或站点开放。

## 开发验证

验证采用真实 PostgreSQL 的独立 SQLx 数据库与合成数据、真实本地 HTTP 上游，
以及前端组件/接口契约自测。所有检查针对当前变更和共享资金/恢复边界；
开发自测与独立验收分开记录。

**自测通过，独立验收未执行。** 以下结果复用输入未改变的已通过检查；失败用例修复后
单独重验，没有把失败执行记录改写为成功，也没有累计宣称完整仓库测试覆盖。

验证过程中发现并修复了两个可见行为问题：所有候选均因授权拒绝时原来被折叠成
`503`，现保留 `403`，真正无可执行路由仍为 `503`；实例面板此前没有挂载到实际
系统信息页，现与原生资源面板同时呈现，并由页面组合测试覆盖。

另有测试环境与夹具修正：重复创建既有身份记录、遗漏历史视图的 runtime 读取授权、
升级保存快照对新增 schema/序列及父表外键触发器的假设均已修正并重验。Auto 用例
保留了撤销用户分组授权即使旧凭证失效的生产行为。丢失提交确认测试要求 TCP，而本轮
数据库只监听私有 Unix socket；该单例通过临时本机字节转发桥重验，原故障注入和
资金断言未修改。环境内存不足时，把两个运维用例及升级 PG 用例移到独立集成目标，
保留真实数据库、权限和业务断言；没有用 mock 代替。

主要可复现命令如下，需先按开发文档准备独立测试 PostgreSQL；资金故障代理测试使用
纯 TCP `DATABASE_URL`。本轮使用锁定依赖、单个编译任务、关闭调试信息和增量编译；
独立集成目标使用 `--config profile.test.package.lmm-core.codegen-units=256` 降低编译峰值。

```bash
cd services/core
cargo test --locked --offline --test operations --test request_limits \
  --test request_operations_upgrade -- --nocapture --test-threads 1
cargo test --locked --offline --test identity_compat -- --nocapture --test-threads 1
cargo test --locked --offline --no-fail-fast --test assembled_billing \
  --test assistant_model --test model_http --test model_recovery_a07 \
  -- --nocapture --test-threads 1
```
