## 真实浏览器与公开定价阻塞

独立审查者在部署后运行实际线上页面，没有替换 API 响应。第二轮六个 Native 场景均核对首页摘要、已加载同源 JS/CSS 与最终 dist，以及 DOM、meta 和运行时 build-id `rv.3a9986d92ce8.2k6e8r7p`。结果为 **5/6，整体 exit 1**：

| 场景 | 结果 |
| --- | --- |
| 1440px 登录页：亮色、暗色 | 2/2 通过 |
| 390px 登录页：亮色、暗色 | 2/2 通过 |
| 工具市场匿名进入 | 通过；跳转登录并保留 `/tool-market` 返回地址 |
| 公开价格目录 | 未通过；真实目录接口返回 `403 pricing_forbidden` |

没有未捕获页面异常或静态资源摘要不匹配；各采样视口没有横向溢出。审查者实际查看代表截图，主审也直接查看了桌面暗色、390px 亮色及价格错误状态三张生产 PNG。

首轮错误地拦截全部 POST，连无凭据的匿名会话检查也被阻止，导致会话中断横幅和回跳失败；该轮 **4/6、exit 1** 的原始证据保留。第二轮仅允许精确的 `POST /api/user/auth/refresh`，六次请求均无 Cookie、Authorization、会话头且请求体为空，实际返回 401。其余六个遥测 POST 被阻止，没有执行账户、配置、资金或模型业务写入。控制台原始错误还包含这些 401、被阻止的遥测及真实价格 403，因此“零未捕获页面异常”不等于“零控制台消息”。这次是修正验收协议，没有为通过验收修改产品代码。

### 价格接口：后端策略与前端声明不一致

Native 的公开状态未提供 `HeaderNavModules`，前端沿用既有默认值 `pricing.enabled=true`、`requireAuth=false`，所以应按公开页面检查，不能固定要求回跳登录。页面实际请求 `GET /core/v1/pricing/public`，返回 38 字节 JSON：

```json
{"error":{"code":"pricing_forbidden"}}
```

另一位审查者只读核对外部 HTTPS、运行中 Core 的现有回环入口及该精确路径的网关上游日志，三者一致：**403 来自 Core，网关正常转发**。外部与 Core 响应的 SHA256 同为 `bfe17b9282fb816406673d2f25a39d42d06db0b9d8361e4a9842e84db0d236dd`。

`pricing/api.ts`、`header-nav-config.ts`、`nav-modules.ts` 在 `561faf51` 与 `3a9986d9` 逐字节一致，两版实际构建产物也包含同样的匿名请求构造。由此可确认请求行为是继承的，没有发现本次修改请求路径的回归；缺少部署前该精确接口的 HTTP 录制，**不能据此确定 403 的起始时间**。

价格页显示读取失败和重试按钮，但标题及过滤栏仍显示零计数。读取失败时模型数量未知，这些 0 不能作为空目录证据。后续需要使 Core 的公开定价权威策略、公开状态的访问声明与前端路由一致，并修正错误状态的未知计数呈现，再分别验收匿名和登录态价格读取。本轮没有放开网关、改变价格权限、修改数据库或将该失败改记为通过。
