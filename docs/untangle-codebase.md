## Behavior that must remain explicit

- HTML attribute escaping, SVG XML escaping, HTML text escaping and Go-compatible JSON hashing use different contracts.
- Rust-bridge version, headers, body limits, error mapping, strict decoding and lack of automatic retries stay unchanged.
- Provider templates preserve header order, the existing exclusions and independent mutable arrays.
- The game move preserves the engine bytes, golden fixtures, state transitions and all test assertions.
- SQL literal extraction preserves exact generated bytes. JSON serialization, financial interpretation, schema, transactions and database credentials stay in their existing owners.
- Module credential translation preserves the original request and runs inside the existing operations authorization guard.
- Wallet preference persistence and payment currency selection are separate behaviors; sharing formatting must preserve each hook's defaults.

## Inventory boundaries

The source tree contains Rust Core, Go Extensions, static Web, build/deployment tools and pinned client submodules. Client submodules and generated protocol/wiki content retain their own owners.

Further Core findings need a decision backed by caller behavior before editing: receipt interpretation shared by usage/history; persisted charging types importing HTTP pricing modules; bounded host shutdown lifecycle; Go-compatible JSON escaping. Similar-looking defaults with different values and type-only import cycles are not treated as mechanical deduplication opportunities.

## Verification

Targeted commands and final commit references will be recorded after implementation. Existing test assertions remain in place. Deployment and production acceptance are separate from this source refactor.
