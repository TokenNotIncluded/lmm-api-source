# LMM API 隱私政策

生效日期：2026 年 7 月 31 日

## 1. 個人資訊處理者

個人資訊處理者：LMM API（維護者：TokenNotIncluded團隊）

聯絡郵箱：[support@lmm.best](mailto:support@lmm.best)

## 2. 我們處理的資訊

為提供服務，我們可能處理：

- 賬戶資訊，例如使用者名稱、郵箱以及您選擇繫結的登入標識；
- 認證與安全資訊，例如密碼摘要、API 金鑰（透過訪問控制保護，並在管理介面預設掩碼展示）、登入時間、IP 地址、裝置和瀏覽器資訊；
- 使用與計費資訊，例如所用模型、請求時間、令牌或請求用量、餘額變動、訂單和錯誤記錄；
- 請求內容，例如您主動提交的提示詞、檔案以及模型生成結果。此類內容僅在轉發請求、返回結果、排障、安全審計或履行法律義務所必需的範圍內處理；
- 您主動提供給客服的通訊內容。

請勿提交無權處理的個人資訊、國家秘密或其他法律禁止處理的內容。

## 3. 處理目的與方式

我們透過自動化系統和必要的人工支援處理資訊，用於建立和保護賬戶、鑑權、轉發模型請求、計算費用、提供客服、排查故障、防止欺詐濫用、改進穩定性以及履行法定義務。我們不會出售您的個人資訊，也不會將您的請求內容用於訓練面向公眾的模型。

## 4. 儲存期限

我們僅在實現上述目的所必需的期間儲存資訊：賬戶資料通常在賬戶存續期間儲存；使用、計費和安全記錄按照排障、爭議處理、安全審計及法定義務所需期限儲存；客服記錄儲存至問題處理完成及合理的爭議期結束。賬戶登出後，我們會在合理期限內刪除或匿名化相關資訊，但法律要求儲存或處理爭議、安全事件所必需的資訊除外。

## 5. 委託處理、共享與跨境傳輸

為完成您選擇的模型請求，我們會向對應的模型或基礎設施提供方傳輸必要的請求內容和技術資訊；支付場景下，訂單所需資訊可能提供給支付服務商。部分提供方可能位於您所在地區之外。我們僅為提供所選服務進行必要傳輸，並要求相關方按照適用規則保護資訊。具體模型及計費條件可在[定價頁面](/pricing)檢視。

## 6. Cookie 與本地儲存

網站可能使用 Cookie 或瀏覽器本地儲存來保持登入狀態、記住介面偏好、儲存安全狀態並改善使用體驗。禁用必要儲存可能導致登入或部分功能無法使用。

## 7. 您的權利

您可以依法請求查閱、複製、更正、補充或刪除個人資訊，撤回基於同意的處理，申請登出賬戶，或要求說明處理規則。請使用註冊郵箱傳送請求至 [support@lmm.best](mailto:support@lmm.best)。為保護賬戶安全，我們可能先核驗您的身份，並在適用法律要求的期限內答覆。

## 8. 安全措施

我們採用訪問控制、許可權隔離、傳輸保護、日誌審計和系統加固等措施降低資訊被未經授權訪問、洩露、篡改或丟失的風險。如發生可能影響您權益的安全事件，我們會採取補救措施，並按適用法律履行通知或報告義務。

## 9. 未成年人

本服務主要面向具備完全民事行為能力的使用者。未成年人應在監護人指導和同意下使用，不應自行提交敏感個人資訊或進行付費。

## 10. 政策更新與聯絡

我們可能因服務或法律要求更新本政策，並在網站公示新的生效日期。有關隱私、投訴或權利請求，請聯絡 [support@lmm.best](mailto:support@lmm.best)。


## 內容安全審查補充說明

內建 AI 助手與 API 安全審計提供預設關閉的 OpenAI Moderation 內容審查功能。管理員可以分別啟用兩項功能，並明確配置適用的賬號分組；未配置的分組保持關閉。

在啟用的範圍內，實際提取的本次待審文字經必要的最小化和脫敏處理後會傳送給 OpenAI 官方 Moderation 介面，用於後臺內容分類。API 僅提取已識別協議中最後一條使用者訊息的文字；內建助手提取本次使用者輸入，並將助手回覆單獨處理，不提交整個請求 JSON、全部歷史對話、系統提示、工具定義或工具結果。未知請求結構不強行提取。文字仍可能含有您主動提交的個人資訊或其他敏感內容；請勿提交無權處理的個人資料或秘密。當前功能僅支援文字，不覆蓋圖片、音訊、影片或檔案二進位制。支援長度內的長文字分塊審查，全部批次成功後才處理分類結果；超限或未實際審查的內容不作完整審查結論。

轉交人工客服的聊天沿用現有私密客服流程，不經過 OpenAI 內容審查，也不作為該功能的 AI 輸入或模型輸出記錄。

平臺透過內部持久化任務佇列處理審查，必要的分類、任務狀態、通知、餘額變動和風險統計記錄用於安全管理、執行已公示規則及處理複核。相關資訊的儲存期限、訪問控制、跨境處理和權利請求繼續適用本隱私政策。使用者輸入與模型輸出分別處理；僅已完成審查的使用者輸入違規統計納入使用者風險分，模型輸出不增加使用者風險分。風險分採用啟發式管理閾值，並與既有錢包風險分取較高值，不代表違法機率或分類可信度；已審查請求數只是計數。金額按最小賬本單位向下取整，實際扣款不超過配置金額及可用正餘額，不足一個賬本單位僅提醒，不產生新欠款。

OpenAI 的處理遵循其適用條款和[官方資料控制說明](https://developers.openai.com/api/docs/guides/your-data)。本補充不承諾平臺或第三方在所有安全、法律場景下均不儲存任何資訊。

具體功能邊界見[安全審查說明](/legal/safety-review.html)，當前分組模式及類別金額見[公開安全規則](/security)。您可透過站內支援或 support@lmm.best 對審查記錄、風險統計與餘額處理申請人工複核；請勿傳送密碼或完整 API Key。
